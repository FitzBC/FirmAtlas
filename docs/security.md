# 不可信固件分析安全基线

固件、压缩包、文件系统、脚本和工具输出全部视为恶意输入。隔离不是后续增强，而是分析平台的前置条件。

## 工作器要求

- 控制面不直接解析或执行固件内容；
- 工作器使用无特权身份、只读输入、一次性工作目录和只写结果通道；
- 默认无网络，按分析器和目标配置最小化出站策略；
- 禁止挂载宿主 Docker socket、凭据目录和控制面数据库；
- 限制 CPU、内存、磁盘、进程数、运行时间、递归深度和展开倍率；
- 分析结束销毁工作区，持久化内容必须经过摘要和类型检查；
- 动态分析与静态分析使用不同信任级别的工作器池。

## 数据要求

- 上传时流式计算摘要，检查声明长度与实际长度；
- 对路径穿越、符号链接逃逸、特殊设备文件、压缩炸弹和稀疏文件防护；
- 原始工具输出编码和转义后再展示；
- 凭据、私钥和个人数据只保存必要证据，展示与导出默认脱敏；
- 所有下载、复核、结论变更和规则变更进入审计记录；
- 保留策略能够按来源许可或组织要求删除 Blob，同时保留合规所需元数据。

## 威胁建模优先项

1. 恶意固件逃逸分析环境；
2. 解包导致资源耗尽；
3. 工具链解析器漏洞被利用；
4. 报告内容在控制台形成存储型注入；
5. 分析器供应链被篡改；
6. 情报源污染导致大规模误报；
7. 多租户之间制品、证据或搜索结果泄露。
