## 2. 恢复出的通信结构

证据链不是“发现了一个 `.cgi` 文件”，而是：

```text
config_ie.js: POST /cgi-bin/cstecgi.cgi + topicurl=getInitCfg
→ lighttpd :80/:8080 + document-root /www/
→ /cgi-bin/ namespace 启用 cgi.assign
→ www/cgi-bin/cstecgi.cgi (ELF32 MIPS)
→ 原生字符串表包含 getInitCfg、setLanCfg 及上传 action 路径
```

Frontend Producer v0.2.0 新增两个通用 construct：

- `custom.request`：从对象式 request 调用恢复字面 URL、方法和 JSON selector；
- `shared-cgi.topicurl`：当 endpoint 配置、wrapper 契约和 prototype selector 同处一个
  source artifact 时恢复逻辑操作。

真实 X5000R 的 `globalConfig.cgiUrl` 与 wrapper 分属 `config.js/topicurl.js`，因此
单文件 Producer 不会硬编码跨文件解析结果。真实 Catalog 使用 `config_ie.js` 中的
完整字面证据确认 shared-CGI 类别，同时把完整动作面和 selector→handler binding
保留为研究案例中的开放义务。

Web Configuration Producer v0.3.0 增加 lighttpd listener、document-root、URL scope
与 `cgi.assign`；同一配置事实多次出现时合并 EvidenceAtom，避免 Catalog 候选身份冲突。
