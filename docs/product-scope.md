# 功能范围与路线图

## 用户工作台

### 固件资产视图

- 厂商、产品、设备型号、发行版和制品谱系；
- 来源、摘要、签名、发布时间、架构、端序、文件系统；
- 同型号版本时间线和任意两个快照对比；
- 分析覆盖度、失败原因和工具版本。

### 详细测绘视图

- 递归文件树、分区和派生制品关系；
- SBOM 与组件版本，支持 CPE、purl、包管理器坐标和模糊身份；
- 启动链、服务、进程角色、用户和权限；
- TCP/UDP、Unix socket、共享内存、消息总线、设备节点等通信方式；
- Web 路由、RPC 方法、CLI 命令、消息主题、认证入口；
- 参数位置、类型、默认值、约束、认证要求及代码/配置证据；
- 证书、公钥、硬编码凭据线索和加密材料（敏感值默认脱敏）。

### 漏洞视图

- 漏洞描述、别名、CVSS、CWE、已利用与利用概率信号；
- 受影响声明与来源冲突；
- 具体固件为什么匹配、为什么排除、还缺什么证据；
- 漏洞对应的组件、文件、接口、端点和可达路径；
- 自动/人工验证结论、修复版本和版本差异；
- 历史时点快照：当时有哪些证据、规则和情报。

### 情报中心

- 官方漏洞库、已利用目录、利用概率和厂商公告的增量同步；
- 按厂商、型号、组件、CPE、purl、关键词和漏洞标识配置关注规则；
- 新漏洞、状态变化、评分变化、公开利用和厂商修复提醒；
- 情报到存量固件的批量重评估；
- 去重、来源优先级、游标、失败重放和同步健康度。

## 角色

- **分析员**：上传固件、检查测绘、复核漏洞匹配、添加证据。
- **漏洞研究员**：追踪漏洞、比较版本、记录验证结论。
- **资产负责人**：关注产品线、查看风险和修复进度。
- **平台管理员**：维护分析器、情报源、配额、隔离策略和审计。

## MVP 验收标准

选择至少两个同型号固件样本，系统应能：

- 按摘要归档且重复上传不复制内容；
- 展示完整解包谱系与每一步失败信息；
- 识别文件、软件包、内核、启动项、监听服务和 Web 路由的一个可验证子集；
- 每个测绘结论可跳转到证据；
- 从至少两个漏洞源关联候选，并区分“确认、可能、排除、待定”；
- 展示两个版本之间的组件、接口和漏洞差异；
- 新情报同步后自动重新评估并生成一条可去重提醒；
- 导出包含运行版本和证据引用的 JSON 报告。

## 分阶段路线图

### P0：可追溯静态分析

- 固件目录、对象存储、任务编排、隔离解包；
- 文件系统与基础 SBOM；
- 服务/端点/基础 Web 路由测绘；
- NVD、CISA KEV、OSV 和 EPSS 同步；
- 漏洞候选、证据评分、版本对比、JSON 报告。

### P1：深度测绘与协作

- 二进制符号、调用关系和配置交叉分析；
- RPC、消息、IPC、设备节点与认证流程；
- 人工复核队列、批注、规则调优和误报抑制；
- 搜索、关系图、看板、通知和团队权限。

### P2：动态验证与规模化

- 仿真/真机动态探测、网络流量和运行时接口发现；
- 漏洞可达性与利用前置条件验证；
- 分析器市场、分布式工作器、租户隔离和配额；
- 对外集成接口及合规报告。

## 暂不进入首版

- 自动生成或执行漏洞利用代码；
- 对公网设备进行主动扫描；
- 将反编译结果当作绝对事实；
- 未经复核自动宣称某固件“存在可利用漏洞”；
- 为尚未出现的部署差异预先拆分微服务。
